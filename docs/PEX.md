# Parasitic extraction (PEX)

`openlayout pex` turns a layout into a transistor-level SPICE netlist with its parasitics, like a
commercial 3D extractor. The netlist includes the resistance of every wire,
contact and via on the signal nets and the capacitance between all nets, for post-layout
simulation in ngspice.

```
openlayout pex <layout.gds> [--cell NAME] [--out FILE] [--mode rc|c] [--rmodel reference|openroad]
               [--schematic cell.sch|cell.spice] [--keep]
               [--cap auto|flat|window] [--window WX,WY] [--halo UM] [--jobs N] [--no-cache]
```

- **From KLayout**: OpenLayout > Run PEX extracts the cell as edited, saved or not. It writes
  `<cell>.pex.spice` next to the layout file and shows the total capacitance per pin. The result
  also goes to the cell's Checks list in the hub.
  It runs in the background, with a window that logs each step and, for a large block, each window
  as its solve finishes (with the time since the start); *Stop* ends the run and its FasterCap
  processes, *Close* hides the window while the run goes on (Run PEX shows it again). KLayout stays
  usable meanwhile, and large blocks are solved several windows at a time (`--jobs`: all cores but
  two, at most 6).
- **From the hub**: the PEX button (Tools > PEX, or `ol.pex(lib, cell)` in the CIW) writes
  `verify/<lib>/<cell>/<cell>.pex.spice`. The summary goes to the CIW and the cell's Checks list.
- **From the shell**: the default output is `<cell>.pex.spice` next to the layout.
  - `--mode c` extracts capacitances only, one node per net.
  - `--rmodel openroad` uses OpenROAD's metal resistances instead of the library's (see
    *Resistance*).
  - `--keep` keeps the working files (FasterCap input, LVSDB).
  - `--cap`, `--window`, `--halo`, `--jobs`, `--no-cache`: large blocks (see *Large blocks*).

The netlist is a `.subckt` with the cell's pins. When the cell has a schematic (`<cell>.sch` next
to the layout, or `--schematic`), the pins follow its order. Library cells follow the CDL order.
Transistors are BSIM-CMG cards, as xschem writes them (`N1 d g s b nmos_rvt l=20n nfin=3`). Nodes
are named `<net>` (the pin) and `<net>_<k>` (inside the net's resistor network).

To use the netlist in a testbench, include it instead of the schematic subcircuit. If the cell is
a library cell, rename the subcircuit, because `asap7.lib` already defines the library cells:

```
.lib asap7.lib tt
.include INVx1.pex.spice
X1 a vdd vss y INVx1_pex
```

A standard cell takes about 3-6 s. About 2-3 s of that is the LVS extraction and the
capacitance solve under 1-3 s. Up to 48 nets, the field solver treats the whole cell as one 3D
problem. Larger blocks are solved window by window (see *Large blocks*).

## How it works

1. **Extraction.** The cell is flattened and its own labels are kept, while the labels of placed
   cells are dropped. Then the ASAP7 LVS deck runs on it in extraction mode (`-rd pex=1`). That
   gives the devices, the nets and their shapes. The mode keeps floating shapes (dummy gates) and
   leaves every finger as its own transistor.
2. **Capacitance: 3D field solver** (`python/openlayout/fieldsolver.py` and
   [FasterCap](https://github.com/iic-jku/FasterCap)).
   - Every net becomes a 3D conductor, built from its shapes and the process description below.
   - The layout is 2.5D, so the z axis is cut at every layer boundary. In each slice a net's
     cross-section is one 2D region. Its edges, extruded through the slice, are the side walls.
     The horizontal faces are where the region changes from one slice to the next, so there are
     no internal faces where a via meets a metal.
   - The source / drain node is a thin plate, and the substrate is a plate under the cell.
   - The dielectric is in layers. FastCap-style interface panels sit at each change of dielectric
     constant, holed where conductors pass through.
   - FasterCap solves the full capacitance matrix with a boundary-element method.
   - Floating conductors (the dummy gates at the cell edges) are grounded, as sign-off extractors do.
3. **Resistance.**
   - KLayout's `RNetExtractor` turns each signal net into a resistor network between its pin and
     the transistor terminals (gate channels and source / drain regions).
   - It counts squares on the gate, LIG, LISD and M1-M9, and adds the contacts and vias.
   - Supply nets (VDD*, VSS*, GND*, ...) stay ideal.
   - Nodes joined by less than 1 mOhm become one node, for example two transistors on one shared
     diffusion. ngspice with the OSDI BSIM-CMG model fails to converge on micro-ohm resistors.
4. **Distribution.**
   - Each net's ground and coupling capacitance is spread over its network nodes in proportion to
     the wire area nearest each node.
   - A coupling goes from each node to the nearest node of the other net.
   - Ground capacitances go to VSS.

## Process description

The description is generated by `pdk/asap7/klayout/pex/gen_pex_tech.py`, which writes
`asap7_pex.json`. Heights are relative to the top of the fins (the source / drain surface). The
fins stand 32 nm above the trench oxide.

| conductor | z (nm) | from |
|---|---|---|
| substrate (plate) | -47 | calibrated: 15 nm under the trench oxide |
| GATE | -32 … 24 | 56 nm thick (reference) |
| source / drain node (plate) | 0, 1 nm off every gate | calibrated (reference: a 1 nm sliver) |
| trench contact (SDT) | 0 … 37 | |
| LIG | 24 … 64 | on the gate; top calibrated |
| LISD | 37 … 64 | 27 nm thick (reference) |
| V0 | 64 … 84 | 20 nm (PDK extraction tech file) |
| M1 / V1 / M2 / V2 / M3 / V3 | 84 … 300, 36 nm each | reference thickness; via heights from the PDK extraction tech file |
| M4 / V4 / M5 / V5 | 48 nm each | tech-file via heights; metal 2 × width |
| M6 / V6 / M7 / V7 / M8 / V8 / M9 | 64 / 64 / 64 / 64 / 80 / 64 / 80 | tech-file via heights; metal 2 × width |

**Dielectric.** There are two dielectrics:

| region | k | basis |
|---|---|---|
| metal stack, above the middle of V0 | 3.23 | fits every plate capacitance between neighbouring layers in the PDK's extraction technology file (`qrcTechFile_typ03_unscaledV02`; its plate coefficients are readable) |
| front end, below the middle of V0 | 4.6 | calibrated |

The front end is denser in a real process: nitride spacers, etch-stop liners and the gate stack
sit between the gate and the source / drain.

### Calibration

The front-end numbers (gate height, substrate depth, source / drain gap, MOL height, front-end
k) are fitted to the library's own reference extraction. Those are the 3D-extracted netlists
that ship with the library, in `$ASAP7_STDCELLS/CDL/xAct3D_extracted` ("the reference" below).

- **Fit set:** the total capacitance of every pin and the couplings between pins of eight cells:
  INVx1, INVx4, BUFx2, NAND2xp33, NOR2xp33, AOI21xp33, XOR2xp5, AND2x2.
- **Score:** RMS of the log errors.
- **Search:** coordinate descent, then a grid over front-end k and source / drain thickness.
  - A thicker source / drain node improves the couplings a little but worsens the pin totals,
    so the node stays a plate.
- **Kept out of the fit:** a single k for everything also fits (k ≈ 4.3). It was rejected
  because it would overstate every routing capacitance on M2 and up by a third.
- **Reproducing it:** the fitting scripts are in `tests/pex/bench/` (see there).

## Resistance

| | sheet at drawn width (Ω/sq) | | via (Ω, nominal cut) |
|---|---|---|---|
| GATE | 6.80 | GCON (LIG on gate) | 10.4 (20 × 18 nm) |
| LIG | 8.33 | SDT (trench contact) | none (the reference has none) |
| LISD | 10.0 | V0 | 19.4 (18 × 18 nm) |
| M1-M3 | 4.20 | V1-V3 | 19.5 (18 × 18 nm) |
| M4 / M5 | 2.87 | V4 / V5 | 11.0 (24 × 24 nm) |
| M6 / M7 | 2.02 | V6 / V7 | 6.2 (32 × 32 nm) |
| M8 / M9 | 1.56 | V8 | 4.0 (40 × 40 nm) |

**Default, `reference`:** this is what the reference netlists use.

- **M1 / M2:** 3.03 Ω/sq on a width 5 nm under drawn, i.e. about 230 Ω/µm for a minimum wire.
  Folded into the drawn width at the minimum width, that is 4.20 Ω/sq. It is exact for minimum
  wires and a little high for wide ones; vias keep their full landing.
- **M3-M9:** the same resistivity, scaled by thickness and width.
- **Gate, LISD, LIG:** the reference values, folded the same way (the gate is drawn 1 nm
  narrower than the reference models it, LISD 3.8 nm wider).
- **Vias:** a single specific resistance from the reference's V1, 6.3e-3 Ω·µm² (19.5 Ω per 18 × 18 nm),
  for V1-V8. OpenROAD's V4-V8 values are within 25 % of it.

**`--rmodel openroad`:** OpenROAD-flow-scripts `platforms/asap7/setRC.tcl` for M1-M9 and V1-V8.
Its M1 is about 3× lower than the reference and its M2 about 8× lower. 30 Ω/µm for an
18 × 36 nm copper wire is close to bulk copper, which is not physical at this size.

Resistance hardly moves the delay of a cell: a transistor's on-resistance is several kΩ. It
matters for long routes.

## Against the library's reference extraction

The benchmark (`tests/pex/bench/bench.py`) runs 54 library cells (176 pins) and 21 delay arcs. It
compares against the reference netlists (ground caps of their `PM_<cell>%<net>` subcircuits plus
their `cc_` couplings).

| | kpex, one dielectric (before) | this model |
|---|---|---|
| input pins: mean / RMS error | -1.5 % / 4.8 % | +3.4 % / 4.3 % |
| output pins: mean / RMS error | -18.2 % / 19.0 % | -5.6 % / 7.6 % |
| delay, 21 arcs (FO2): mean / RMS | -2.9 % / 4.6 % | -0.3 % / 3.7 % |
| parasitic delay captured (vs schematic) | 89 % | 100 % |

Examples (total capacitance per pin, fF):

| cell | pin | before | now | reference |
|---|---|---|---|---|
| INVx1 | A / Y | 0.199 / 0.140 | 0.217 / 0.167 | 0.210 / 0.192 |
| INVx4 | A / Y | 0.675 / 0.338 | 0.726 / 0.393 | 0.707 / 0.388 |
| BUFx2 | A / Y | 0.181 / 0.184 | 0.204 / 0.209 | 0.223 / 0.208 |
| NAND2xp33 | A / B / Y | 0.148 / 0.140 / 0.115 | 0.151 / 0.141 / 0.131 | 0.142 / 0.135 / 0.144 |
| XOR2xp5 | A / B / Y | 0.395 / 0.349 / 0.233 | 0.404 / 0.363 / 0.271 | 0.385 / 0.349 / 0.305 |
| FAx1 | A / CON / SN | 0.708 / 0.417 / 0.215 | 0.721 / 0.457 / 0.241 | 0.678 / 0.447 / 0.242 |
| DFFHQNx1 | CLK / D / QN | 0.186 / 0.213 / 0.148 | 0.183 / 0.208 / 0.169 | 0.175 / 0.200 / 0.194 |

**What remains.**

- **Inputs** come out a few % high.
- **Single-stage outputs** come out 5-13 % low (outputs behind a buffer stage match). That is
  the source / drain node's coupling to the gates beside it.
- **Delay:**
  - Most arcs come within 0.5-3 % of the reference, slightly under.
  - Three arcs come out 7-10 % slower: AOI21 A1→Y, OAI21 B→Y and XOR2 B→Y. Each goes through an
    internal node of a transistor stack. The reference **extracts nothing** on unlabelled internal
    nets (`noxref_*`): not one capacitor in its netlists touches one. So there the difference is
    the reference leaving out real wiring (for AOI21's PMOS stack node, 0.14 fF of M1 / LISD).

## Large blocks: window by window

One FasterCap solve of a whole block takes time roughly proportional to the square of its net count.
A 10T bit cell (16 nets) takes 3 s, a row of 8 (107 nets) 5 min, two rows (197 nets) 16 min, and an
array of thousands of cells would not finish. Above 48 nets, `openlayout pex` therefore solves the
capacitances window by window. `--cap window` forces this mode and `--cap flat` turns it off.

1. **Windows.** The block is cut into a grid of windows the size of the cell that covers most of
   it (an array's bit cell, not the vias placed on it), or `--window WX,WY` µm. The grid is shifted so that its edges cut across
   wires rather than along them. This matters for mirrored rows, which put the shared rail exactly
   on the cell edge: a rail cut along its length cost VDD 5 % of accuracy. The outer windows reach
   to the block's edges.
2. **One solve per window, with its context.** Each window is solved with at least `--halo`
   (0.1 µm) of context around it. Each axis's halo is widened by up to 50 nm, so that the context's
   outer edges also cross wires. A shape cut along its length there leaves a sliver that shields
   too little: on the narrow INVx1, a plain 0.1 µm halo came out 5.7 % low. The conductors are:
   - the pieces of the nets inside the window;
   - the same nets' pieces in the context, 5 nm apart from the window's;
   - the substrate under both.

   The window's rows of the capacitance matrix, with each net's pieces summed, are its share: its
   ground capacitance and its coupling to every net, inside or outside the window. These rows are
   exact for the window's conductors, because the context is at 0 V whenever one of them is
   driven. A coupling between nets of two windows is the mean of what the two windows see.
3. **Alike windows are solved once.** A window's key is its shapes and its context's, moved to the
   origin, with the nets numbered by their shapes. In an array most windows are alike:
   - a row of cells has 3 kinds of window (the two ends and the middle);
   - any larger array with mirrored rows has 12.

   The solve count stays the same as the array grows. `--jobs N` runs N solves at a time. Results
   are kept in `~/.cache/openlayout/pex` (`--no-cache` solves everything again), so a block
   extracted again solves only the windows that changed.
4. **Capacitors where they are.** Each window's share goes onto the nodes of the R networks inside
   the window, by wire area, rather than being spread along the whole net (a word line no longer
   carries every cell's coupling at every node). Couplings under 0.5 % of both nets' totals become
   ground capacitance, which keeps the totals and keeps large netlists sparse.

Measured on a 10T compute-in-memory bit cell (SRAMCIMsbc, 0.54 × 0.27 µm), tiled with odd rows
mirrored. The flat times are FasterCap on 4 threads. "Windowed" is the whole `openlayout pex`,
single-threaded with one solve at a time (FasterCap on one thread is some 1.8 times slower than on
four). The percentages compare each net's total capacitance against flat: the mean and the largest
error over the signal nets, labelled and unlabelled, VDD included.

| array | nets | flat: FasterCap | windows / solved | windowed | `--jobs 6` | vs flat | capacitors flat → windowed |
|---|---|---|---|---|---|---|---|
| 1 × 8 | 107 | 322 s | 8 / 3 | 37 s | | mean 0.4 %, max 1.5 % | 3684 → 1814 |
| 2 × 8 | 197 | 971 s | 16 / 6 | 166 s | 54 s | mean 0.5 %, max 1.7 % | 17662 → 4974 |
| 4 × 8 | 377 | stopped after 66 h ‡ | 32 / 12 | 539 s | 205 s | — | — → 13362 |
| 64 × 80 | 56609 | — | 5120 / 12 | | 9-15 min † | | 2.4 M capacitors |

‡ The flat 4 × 8 solve (FasterCap -a0.05) was stopped unfinished after 66 h and more than 70
CPU-hours: 1.9 times the nets of 2 × 8 had cost more than 9 times the CPU time.

† 0.1-0.15 µm halo, FasterCap on 2 threads, run beside other jobs. The 64 × 80 array is 51 200
transistors: the whole RC extraction, 288 000 resistors, peaked at 2.9 GB. Its LVS extraction took
40 s and its R networks 70-100 s.

- **VSS is left out.** Its total depends most on the substrate around the block, and it is ground
  in a simulation. VSS comes out some 7-9 % under flat, because the flat solve's substrate plate
  reaches 0.3 µm past the block on every side.
- **The windowed netlist simulates faster.** The 1 × 8 netlist took ngspice 8 s against 15 s for
  the flat one (6 ns transient).
- **A flat netlist of 50 000 transistors is too much for ngspice.** On the 64 × 80 netlist,
  ngspice had not started its transient after 31 min at 4.8 GB. Simulating at this size needs a
  subcircuit per kind of window, fewer coupling capacitors, or a faster simulator.

### What is left

- **Netlists for simulation at scale.** One subcircuit per kind of window, instanced per window
  (the R networks cross windows, so they would be cut at the window edges), and a coarser coupling
  threshold for large blocks.
- **Periphery and routing.** Windows away from the array (adders, drivers, top-level routing) are
  rarely alike, so each costs a solve. That is fine for some tens of them. For a large periphery:
  windows the size of the periphery's cells (or a fixed `--window`) and `--jobs`.
- **Delays flat vs windowed.** A post-layout simulation that switches the cells: the 1 × 8
  testbench used so far never switches its output.

## Speed

This is the capacitance solve alone (FasterCap on 4 cores). The whole `openlayout pex` adds about
2-3 s for the LVS extraction.

| FasterCap setting | INVx1 | NAND2x1 | XOR2xp5 | DFFHQNx1 | vs a converged solve |
|---|---|---|---|---|---|
| **default:** -a0.05, 30 nm panels | 1.2 s | 2.1 s | 2.8 s | 9.7 s | -3.6 … -5.3 % |
| -a0.02, 30 nm panels | 1.3 s | 4.1 s | 6.2 s | 22 s | -2.0 … -3.6 % |
| -a0.05, 60 nm panels | 0.4 s | 2.4 s | 1.4 s | 5.2 s | -4.5 … -5.7 % |
| converged: -a0.01, 15 nm panels | 101 s | 302 s | 27 s | 153 s | — |
| (before: kpex, one dielectric) | ~8 s | | | | |

- **The default is a few % under a converged solve, uniformly.** The error never exceeds its RMS
  by much, so it is a bias rather than noise.
- **The calibration absorbs it.** It ran at the same settings, and the remaining cell-to-cell
  spread is about ±1 %. If the solver settings change (`MAX_EDGE`, `ACCURACY` in `pex.py`), the
  front end has to be recalibrated.
- **What changed from kpex:**
  - The substrate no longer touches the gate (coincident faces stall the solver).
  - The panels are rectangles at most 30 nm long rather than a fine Delaunay mesh.
  - The window around the cell is 0.3 µm.

## Tests

- `tests/pex/test_pex.py` (in `openlayout doctor`):
  - the field solver against parallel plates (one and two dielectrics);
  - INVx1 and NAND2xp33 against the reference (inputs ±10 %, outputs -20 / +10 %);
  - transistor cards and pin order;
  - resistor networks on the signal nets, with the supplies ideal;
  - the output network against the reference's, and `--rmodel openroad` below it;
  - a hierarchical layout (placed cell, its own labels), giving the same capacitances as the cell;
  - `--mode c`;
  - a 2 × 4 array of INVx1 window by window: 6 kinds of window solved once each, totals within
    5 % of a flat solve, and a second run taking every window from the cache;
  - a post-layout ngspice simulation in which the parasitics slow the inverter down.
- `tests/pex/bench/`: the benchmark and calibration scripts above (minutes to hours, not in
  doctor).
- `tests/pex/bench/windows.py`: a cell tiled into an array, extracted window by window and
  (`--flat`) in one solve, with the totals compared.
- `tests/klayout/test_lvs_gui.py`: OpenLayout > Run PEX on a workarea cell.
- `tests/python/test_hub.py`: the hub's PEX button.

## Install

`setup/install.sh fastercap` builds FasterCap from source (pinned in `setup/versions.env`, with its
LinAlgebra / Geometry siblings and wxWidgets 3.2) into `/usr/local/bin/FasterCap`. FasterCap is
LGPL-2.1 and runs as a separate program. `setup/install.sh python` installs the `klayout` Python
module into the venv. `openlayout doctor` runs the PEX tests.
